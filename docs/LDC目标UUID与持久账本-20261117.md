# LDC 目标 UUID 与持久账本修复记录（2026-11-17）

本批解决“请求已发出，但受理响应丢失后没有目标 UUID 可供查询”的追踪缺口，并把目标身份与终态写入独立账本。整体自动建图与跨运行恢复尚未完成，自动入口继续隔离。

## 行为变化

- Bridge 在调用 `send_goal_async(..., goal_uuid=...)` 前生成 UUID，并将 UUID、boot/run、Action 名称、输入速度话题、地图、目标与控制页面写入账本；prepare 失败不发 RPC。
- 受理、取消请求及取消 ACK 均不视为终态。明确拒绝或 ROS 结果状态 4/5/6，且终态落盘成功，才解除内存目标屏障。
- 终态落盘失败保留远端已知结果和未确认屏障；存储恢复后可通过明确取消操作重试落盘，不自动续跑。
- 取消证据写入失败不阻止取消 RPC。锁定时先发布零速/急停，再执行撤权、取消及存储操作。
- `goal_dispatched` 保留兼容，但只表示准备；`action_sent` 表示请求已提交，仍不等于受理。

## 路径、容量与限制

`LDC_ACTION_JOURNAL_PATH` 可显式指定路径；默认实车账本为 `~/.local/share/ldc/control/domainN/actions.sqlite3`。仿真有日志目录时使用该目录内 `action-journal.sqlite3`，否则使用独立 simulation/control 路径。全部测试 fixture 显式使用内存库，持久化测试仅用临时目录。

SQLite 使用 FULL 同步、立即锁失败，不覆盖不属于本应用的数据库；拒绝损坏库及目标/直接父目录符号链接。未确认目标最多 256 条，终态历史最多 128 条，每目标证据最多 32 条。不自动删除未确认目标。

**当前不提供启动后消费旧账本、isolated_unknown 恢复及完整 Nav2 namespace 隔离。** 当前根 Action 名称仍为 `/navigate_to_pose`，不同运行的内部 `cmd_vel_nav` 仍共享；不得据本批声称旧任务来源已完整隔离。新鲜末端话题不能解决旧控制器进入新 smoother 的问题。下一批必须隔离 Action、内部速度、生命周期、地图/定位与 TF 来源，之后才接入旧 run 恢复。

SQLite FULL 的 fsync 仍可能阻塞 ROS 线程；`timeout=0` 仅消除数据库锁等待，不保证磁盘卡顿下的取消或停车延迟。实车安全门控继续独立生效，本批未做硬件停车时延验收。
