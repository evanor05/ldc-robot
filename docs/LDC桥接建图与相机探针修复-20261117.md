# LDC 桥接、建图与相机探针修复（2026-11-17）

本批结合本地报错、红绿回归与指定 DSH 决策完成软件修复。未操作实车、未刷固件、未改动力参数和默认导航算法。整个优化目标仍在进行，自动建图授权和实车地图适用性尚未完成。

## 修复行为

### 控制输入与退出

`scripts/navigation_bridge.py` 的 `Bridge()` 默认不读取 stdin；生产 `main()` 显式传入 stdin。测试不再过滤 shutdown 或替换队列来掩盖后台线程竞态。

输入仅接受 JSON 对象。EOF 或输入读取异常恰好入队一次 shutdown；ROS 线程负责取消、锁定和零速，输入线程不直接发布运动指令。生产 main 的退出锁定保留。

`web_console/managedProcess.js` 先捕获进程树和直接子进程退出事件，终止后既确认已捕获后代不再运行，也确认 Node 已处理直接子进程退出。保留 `{pid}` 调用、TERM→KILL 超时与 PID 启动时间核对，失败不伪装为成功。

原网页回归的 Stop 响应曾出现 `job.running=true`。新增测试通过同步等待 Linux 僵尸态，稳定重现“系统已停止、Node 尚未回收”的窗口；修复后确认退出字段和 PID 消失，保留原并发测试强度。

限制：首次扫描前父进程已退出并使孙进程成为孤儿时，当前实现不能保证找回全部孤儿；本批不宣传覆盖任意早退父进程。

### 保存成功再停止

`web_console/server.js` 在地图保存失败后返回 `success=false, stopped=false, saveFailed=true`，保留建图进程、开始时间、运行代次与未结束的运行清单，释放保存状态供人工重试。

I/O、超时、文件不完整、时长及质量拒绝均不能落入停止流程。保存成功后才终止；终止失败仍报告失败。明确的“不保存中止”与 `?save=false` 路径保留，重复停止不生成另一张地图。

这修复了本批初次隔离验收中 EACCES 后仍停止 GMapping 的真实失败。网页原有 `stopped=true` 兼容分支保留，用来反映旧后端或其它已确认停止的错误响应。

### 仿真保持隔离

`scripts/start_mapping_task.sh` 在显式 `ROBOT_SIMULATION=1` 时选择 `ldc_environment --sim`，保持 Domain197、本机发现及 UDPv4；默认及 0 选择实车模式，支持原有 `ROBOT_REAL_DOMAIN_ID`。替身启动器检查最终环境，不为验证默认模式启动真实 ROS。

本批再次发现：实车当前地图质量门槛为 occupied≥2500、整幅画布 unknown≤85%，没有已核实的实车标定依据。6×4.5m 合成房间约 412 个障碍栅格，整幅未知占比约92.9%，因此完整链路被该门槛阻断。增加未知留边即可改变比例，这个统计量不能独立证明地图好坏。

为独立验证软件链路，`scripts/offline_console.py` 显式设置合成房间策略：occupied≥300、unknown≤95%、resolution=0.05m；`web_console/simulationMapPolicy.js` 仅在仿真标志和 Domain197 同时成立时接受该覆盖，非法参数拒绝。没有显式策略则保留配置值。保存、列表与导航仍使用同一个生效策略；隔离验收强制 `ROBOT_MAP_QUALITY=strict`，不使用 Node 单元测试豁免。

每次运行保存 `map-policy.json`，并在验收报告中记录测试门槛、原实车配置及 `realPolicyValidated=false`。本批未修改 `ros_config.json` 的实车阈值，也没有证明这些值适合实际房间。

### 相机源诊断

`scripts/vision/source_probe.py` 增加 URL/端口/有限正超时校验、64KiB HTTP头上限、4MiB首帧累计数据上限、8192单边及16Mi像素的解码前检查。

只解析一次 DNS，固定尝试首个地址，不做多地址回退；HTTP 与首帧按阶段绝对截止设置每次 I/O 剩余时间，失败记录已进入阶段的耗时。HTTP半头EOF归HTTP失败，迟到解码不能报告健康；仍要求实际可解码的JPEG。

拒绝输入先使用展示占位符，全部校验通过且不含userinfo后才记录展示URL，避免非法超时、超长URL、控制字符等提前返回分支回显虚构测试凭据。此保证针对userinfo拒绝分支，不是对任意path/query令牌的通用脱敏。

DNS解析和Pillow原生解码没有硬实时截止保证；网络超时与容量边界不能被描述为整个调用的绝对完成时限。未更改实时相机采集、YOLO模型或固件。

## 自动建图状态：只隔离，未完成

网页 `mode=auto` 在预检、取得控制权和启动进程之前返回409及 `AUTO_MAPPING_AUTHORITY_UNVERIFIED`；日常建图脚本 `--auto` 返回2，手动GMapping保留。

原因是 Bridge 与独立 `cmd_vel_gate` 同时发布 `/cmd_vel`，gate尚无页面租约与完整接管闭环。直接 `auto_mapping.launch.py` 仍是未完成授权的开发入口；不能因为日常入口已拒绝就称所有入口安全。后续必须完成统一最终发布者、默认闭锁、租约失联停车、手动接管确认、急停及重启不续跑，再重新开放。
