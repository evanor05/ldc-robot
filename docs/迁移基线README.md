# ROS / 车辆控制迁移基线

源环境：Ubuntu 22.04.5、x86_64、VMware、ROS 2 Humble。
目标：先完整保全，随后在 Ubuntu 26.04 中适配；本仓库不是已通过目标系统测试的安装包。

## 交付分层

1. 本 Git 仓库：脱敏后的工程源码、模型、地图、配置和说明。配置中的敏感值会被替换；不能直接视为实车配置。
2. 私有 Release 附件：加密的原样备份，保留本机未提交内容、原始 Git 历史、工具链、构建结果和依赖。Docker 另行导出。
3. **本地密钥**：源机 `/home/<user>/Desktop/ros-car-migration-20261019/KEEP-LOCAL-backup.key`。必须通过独立的安全方式带到目标机，绝不提交到 Git 或上传 Release。丢失后无法解密。

最终完成状态以 `migration-status.json` 为准。存在阻塞或未上传附件时，不应认定迁移完成。

## 恢复前先验证

下载全部附件到同一目录，核对 `SHA256SUMS`。如附件进行了分片，按分片清单顺序合并，再检查原文件校验和。

解密至隔离目录检查，**不要直接覆盖 Ubuntu 26.04 的根目录或系统配置**：

```bash
set -o pipefail
mkdir -p "$HOME/ros-car-original"
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 \
  -pass file:/安全位置/KEEP-LOCAL-backup.key \
  -in user-projects.tar.zst.enc \
  | zstd -d | tar -xpf - -C "$HOME/ros-car-original"
```

归档使用原路径去掉开头 `/` 的布局。工具链和 ROS 旧二进制仅用于保全与对照，不保证在新系统直接运行。系统配置备份可能含口令和网络凭据，须保护密钥和解密文件。

Docker 镜像归档解密后使用 `docker image load`；容器配置、网络、卷与绑定挂载数据需要结合备份的 inspect 信息恢复。容器 export 只是文件系统快照，不替代镜像和容器配置。不得将旧 Docker 数据根目录直接覆盖新系统。

## 已知问题

- 源码有未提交修改、未跟踪包和被删除的雷达子模块；只有重新克隆上游仓库是不完整的。
- 旧总启动文件依赖缺失的 YDLIDAR ROS 包；旧安装结果与当前源码不完全一致。
- 本地主机 MAVLink 配置为 921600，固件源码 UART 为 230400；需确认实车版本后统一。
- micro-ROS 与 MAVLink 是车端可选模式，实际模式保存在车端配置中，尚未读取。
- 网页电池话题与固件协议存在差异；IP、地图路径和服务路径需在目标机调整。
- 旧 systemd 网页服务指向不存在的旧目录。
- 主机文件备份不包含车端 Flash/NVS 的实际运行参数；实车 Wi-Fi、PID、通信模式和烧录版本需要单独记录。
- 在目标系统上先验证通信和停止保护，再验证传感器、建图、导航与界面；不要直接实车执行旧总启动文件。
