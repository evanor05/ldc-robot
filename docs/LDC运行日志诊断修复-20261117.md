# LDC 运行日志诊断修复（2026-11-17）

本批以当前仓库、DSH 历史和三份实车运行日志为依据，修复诊断报告与网络采样器。技术裁决来自 DSH 子会话 `b83a720b-a521-424a-b414-5b7186362206 → magpie/codex/gpt-6-astra`，已经项目指定脚本核验；原始裁决和核验输出保存在审计目录。没有操作实车或改变导航算法。

## 修复内容

- 有断流、零/低传感器有效率、导航/前端错误、后端不可达或未闭合断连时，报告明确显示异常，不再以“没有建议”推导健康。
- 缺文件、空日志、坏 JSON、非对象记录、缺类型/时间/健康字段会列为证据缺失；已知异常与缺失证据并列显示。`assessment` 区分 `issues_detected`、`insufficient_evidence`、`no_observed_anomalies`，最后一项只表示已采集范围内没有观察到异常。
- ping 分列实际尝试、成功、失败、结果未知。失败比例以已知成功/失败结果为分母，未知结果与未采样另行提示。无尝试时 `pingFailures` 和 `pingFailureRatio` 为 null，不能把它当成网络正常。
- console 缺失、空白或无法解析时 `microRosRebuilds=null`；有效日志只报告观测到的重建，另报尚未闭合的断开记录。报告中的主机急停事件不再标成已经证实的硬件急停。
- 5 秒滑窗超限统计称为“超限采样窗口”，可能重复覆盖同一空洞；独立断流次数仍按事件统计。报告不再单凭空洞就归因雷达供电、串口或 Wi-Fi。
- 网络六项累计计数各自维护基准。首次、字段缺失后恢复、切换接口的差值为 null；回退差值为 0 并列入 `resets`，下一样从新值继续计算。
- 采样命令使用 argv 与 `shell=False`，校验 IP 和接口名。命令失败/不可解析时 Wi-Fi 连接与省电状态返回未知，不伪装为已连接或关闭省电。

现有采样 JSON 字段保留；报告新增上述证据和结论字段。外部消费者需接受未知值 null，不能把 null 转换成 0。
